# MG023 review of MG7 Draft 1

**Recommend a Draft 2 before registration.** Keep the two endpoints, reuse the frozen MG6 midpoint and keep the directional change as the primary gate. The static contrast survives using the production measurement. The main risks are loading the wrong initial fields, overstating what the gate tests, and treating an imprecise proportionality estimate as agreement.

Reviewed ModelG revision `b1badf73a6ff77134b6e9ca5dfa2151ee1ffe9bd`. I used archived MG4c fields and the MG6 measurement routines from the MG022 checkout for a static check. No MG7 evolution, timing pilot or production run was performed.

## Independent design check

I reproduced all five mean node-sum predictions and negative-well integrals in §2. Using the MG6 smoothed-X detector, its fixed b = 28 threshold, and its area quadrature instead of the raw X minimum and equal node weights gives mean P₀(1.5) of −35.00, −37.72, −39.49, −41.23 and −44.78 nodes in ascending b order. The endpoint differences by start are −3.94, −18.29, −10.48 and −6.43 nodes. All 20 archived states detect single under both the common and MG4c b-specific thresholds. The largest initial nodal φ_G is 0.0564, below the proposed 0.14 margin. The design signal is real but uneven across starts. The weakest start matters because one reversed sign prevents a positive gate.

## Changes before registration

1. **Require the actual endpoint fields.** The inherited MG6 driver calls `run_mg5.start_state(slot, pl, b)`. That function always opens the b = 28 field and shifts its steady-state reference. Passing 27.5 or 28.5 to it silently initializes a different experiment. Load the actual MG4c final array at each requested b without that shift. Verify the source hash and array equality before launch, test that the reaction parameter is the requested b, and include b in every run key. Freeze the detector threshold. I favor the common MG6 threshold −4.45758 to preserve the observable across b, with the MG4c thresholds (−3.85703 and −4.84027) as a descriptive sensitivity check from sparse records.
2. **Correct the target and name the finding precisely.** Candidate intensity νρ₀F times acceptance exp(κφ_G)/F gives birth intensity νρ₀ exp(κφ_G). With death rate ν, the frozen-field target is ρ₀ exp(κφ_G). Section 1 retains an extra 1/F. The design calculation already uses the correct normalization. The primary gate tests a larger coupled-minus-shifted deficit at the higher endpoint. It does not require proportionality, monotonicity through b = 28, or even a negative contrast at either endpoint. If TRACKS is retained, define it explicitly as a directional endpoint result. Report both endpoint contrasts and the midpoint separately. The well integral grows while its measured width changes little, so describe a stronger well rather than assuming a larger radius.
3. **Compare the same quantities for proportionality.** The numerator differences CP2 minus SH2 across endpoints, but the denominator differences CP2 predictions alone. Use the corresponding difference of predicted CP2 minus predicted SH2, which MG6 already records, or compare CP-only observations with CP-only predictions and label that secondary estimand. Separate predictions based on the starting fields from predictions based on the evolving coupled fields. Only the former are available before the run. Agreement with the latter tests the local density response conditional on the realized wells.
4. **Replace the interval-includes-one rule.** A wide or unbounded ratio interval can contain one even if it rules out almost nothing. Report the mean paired residual (observed change minus matched predicted change) and its conditional 95% interval in nodes. If quantitative agreement is to earn a label, have the PI choose a scientifically meaningful error tolerance before launch and require the entire interval to lie within it. Otherwise leave agreement descriptive. A ratio can accompany the residual with a paired Fieller interval and explicit handling for a denominator indistinguishable from zero. Do not pool eleven checks per run as independent observations.
5. **Match the design to the uncertainty claim.** MG6's SD of 3.7–3.9 measures variation of a contrast at one b, not the SD of a difference between two b values. The four measured static endpoint differences themselves range over 14 nodes. The draft's SD of roughly 5 and its feedback multiplier are planning scenarios, not demonstrated power. I favor using one public candidate seed and one shift per start across the two endpoints, as well as across matched arms where applicable. This holds the random environment fixed when changing b, while each start retains its own stream. Specify this before any run. Distinct endpoint streams also give a valid contrast if retained, but add variation. The four starts are two placements on each of two graphs. Interpret the conditional t interval on that fixed panel. Treat a pooled slope over 12 CP2 runs as descriptive and show the four within-start trajectories beside it.
6. **Bound the numerical exception and make Part 0 executable as a decision.** The centre waiver applied to a particular check at b = 28. Step and tick agreement at b = 27.5 and 28.5 have not been demonstrated. Compare the registered and refined discretizations on an unregistered start/stream at each endpoint, using a coupled arm and a window long enough to compare the actual count observable. Keep candidate histories paired as in the corresponding MG6 checks, distinguish forced-history step checks from free-acceptance tick checks, and freeze tolerances and stop rules before seeing endpoints. If the PI elects to transfer validation without these checks, record this explicitly as a new exception. A ten-unit timing run measures throughput, not accuracy of a late-window change of order ten nodes. Specify hash, single-start, bound, timing-completion and budget failures as launch stops, and keep calibration seeds separate from production. State that incomplete or invalid runs preclude scoring before applying feedback or significance rules.

## PI decisions in §10

| Decision | Recommendation and rationale |
|---|---|
| 1. Endpoints | Keep 27.5 and 28.5 and the recorded b = 28 midpoint. The endpoint sign survives the production quadrature on all four starts. Pin the MG6 input revision. |
| 2. Arms | Keep CP2 and SH2. Their difference answers the registered spatial-coupling question directly. SH2's near agreement with DEC at b = 28 need not be assumed at the endpoints. |
| 3. Shuffle | Drop SF2 from MG7. Four midpoint runs do not improve the endpoint test. If retained, use MG6's midpoint candidate streams for the comparison, a separate deterministic permutation stream, and define which field is used for transfer and prediction. Permuting nodal values preserves their multiset but generally changes the distribution after interpolation at candidate positions. |
| 4. Part 0 | Verify endpoint files, detector and bound, and add the targeted endpoint refinement check above. No need to repeat all of MG6 calibration. |
| 5. Window | Keep t = 100–200 fixed. Define drift with an absolute block difference and an explicit reference prediction. Earlier blocks at 60–100 cannot establish stationarity throughout 100–200. Report the within-window trajectories or early/late window differences for CP2 and SH2, with no post hoc window change. |
| 6. Budget | Adopt 90 production ledger hours, 22-run cap and eight workers if SF2 is dropped. The actual MG6 CP2 and SH2 averages were 82.6 and 84.3 seconds per unit, consistent with about 74–75 hours for 16 runs. Price validation separately, define what spare slots may be used for, and require a recorded PI decision if the projection exceeds the cutoff. Never replace an unfavorable physical outcome. |
